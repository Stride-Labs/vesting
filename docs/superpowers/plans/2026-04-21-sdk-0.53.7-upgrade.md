# Cosmos SDK 0.53.7 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump `github.com/evmos/vesting` from cosmos-sdk v0.50.14 to v0.53.7 with the absolute minimum code changes required to keep it compiling and passing existing tests.

**Architecture:** Single-module standalone library. Compiler-driven fixes on top of a `go.mod` dep bump. No architectural changes. All fixes delivered in one squash commit at the end.

**Tech Stack:** Go 1.23, cosmos-sdk v0.53.7, cometbft v0.38.21, cosmossdk.io/{core,store,math,errors,log,api,x/tx}, gogoproto.

## Commit Discipline

The user asked for a **single commit**. Do not commit after each task — only stage. The final task runs verification and creates one commit. If work is interrupted mid-plan, the branch tip before Task 1 is the rollback point (`git reset --hard <tip-before-task-1>`).

Write the categorized list as a short note (in the commit message draft or a scratch file). This list drives Tasks 3–8.

## Task 4: Fix Interface Registration and Account Type (`x/vesting/types/codec.go` and `clawback_vesting_account.go`)

**Files:**
- Modify: `x/vesting/types/codec.go`
- Modify: `x/vesting/types/clawback_vesting_account.go`

**Likely breakage:** `sdk.AccountI` may have added required methods in 0.53. The SDK's own `BaseVestingAccount` (which we embed) should satisfy these, and our `ClawbackVestingAccount` inherits them by embedding — so most likely this compiles as-is. But if 0.53 added methods that `BaseVestingAccount` itself doesn't satisfy (e.g., a new `GetSequence` variant), we'd need a stub. Check the error log.

The `GenesisAccount` interface is stable. `govv1beta1.Content` registration is stable.

- [ ] **Step 4.1: Check `codec.go` against the error log**

If `codec.go` has no errors in `/tmp/sdk53-build-errors.log`, skip to Step 4.3.

If it does have errors, the most likely one is around `sdk.AccountI` or `authtypes.GenesisAccount` registration — the fix is usually adjusting the import path or the type assertion target. Fetch the relevant SDK 0.53.7 source to confirm the correct form.

- [ ] **Step 4.2: Apply the minimal fix to `codec.go`**

Make only the change required by the compile error. Do not touch unaffected registrations.

- [ ] **Step 4.3: Check `clawback_vesting_account.go` against the error log**

If no errors, skip to Step 4.5.

If there are "missing method" errors on `*ClawbackVestingAccount` for `sdk.AccountI` or `authtypes.GenesisAccount`:

1. Look up the method signature in the SDK 0.53.7 interface definition.
2. If the embedded `BaseVestingAccount` has it, we inherit — the error shouldn't appear.
3. If `BaseVestingAccount` doesn't have it either, both our type and the embedded type need it. Since we don't modify the SDK, this is a sign the interface contract genuinely changed — add a minimal stub on `ClawbackVestingAccount` that delegates to `BaseVestingAccount` where possible, or returns a zero value with a comment pointing at the upgrade.

- [ ] **Step 4.4: Apply minimal stubs only where forced**

Keep stubs short. Example shape (adjust to actual method):

```go
// NewMethodName added for sdk v0.53 AccountI compatibility.
func (va ClawbackVestingAccount) NewMethodName() ReturnType {
    return va.BaseVestingAccount.NewMethodName()
}
```
