# Cosmos SDK 0.54.2 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump `github.com/evmos/vesting` from cosmos-sdk v0.53.7 to v0.54.2 with the absolute minimum code changes required to keep it compiling and passing existing tests.

**Architecture:** Single-module standalone library. Compiler-driven fixes on top of a `go.mod` dep bump. No architectural changes.

**Tech Stack:** Go 1.23+ (may bump), cosmos-sdk v0.54.2, cometbft v0.39.1, cosmossdk.io/{core,math,errors}, `cosmossdk.io/log/v2`, `github.com/cosmos/cosmos-sdk/store/v2/types`, gogoproto.

## Commit Discipline

The user asked for the changes to be **left unstaged** at the end. Do not stage and do not commit at any point. If work is interrupted mid-plan, the branch tip before Task 1 is the rollback point (`git restore .`).

## Task 2: Capture the Compile-Error Landscape

**Files:**
- None modified in this task. This is discovery.

- [ ] **Step 2.1: Run a full build and capture errors**

Run: `go build ./... 2>&1 | tee /tmp/sdk54-build-errors.log`
Expected: build fails with a list of errors. Do not panic — this is expected.

- [ ] **Step 2.2: Categorize the errors**

Open `/tmp/sdk54-build-errors.log` and group errors by file. Categories (same taxonomy as the 0.53 plan):

1. **Renamed/moved symbol** (e.g., `undefined: foo.Bar`) — fix by updating the identifier.
2. **Changed method signature** on a keeper interface method — fix by updating our interface to match the SDK's new signature.
3. **Missing interface method** (e.g., `*ClawbackVestingAccount does not implement sdk.AccountI: missing method Foo`) — fix by adding a stub method.
4. **Removed symbol** — fix by replacing with the 0.54 equivalent (consult simapp).
5. **Proto-generated code error** in `.pb.go` files — flag for Task 7.

Tasks 3–6 cover the likely affected files in turn. If a file has no errors in the log, skip its task.

## Task 4: Fix Expected Keepers and Account Types (`x/vesting/types/`)

**Files:**
- Modify (as needed): `x/vesting/types/interfaces.go`
- Modify (as needed): `x/vesting/types/clawback_vesting_account.go`
- Modify (as needed): `x/vesting/types/codec.go`

**Likely breakage:** any keeper interface method whose SDK 0.54 signature differs from 0.53. The most likely candidates (per the design spec):

- `BankKeeper.BlockedAddr(addr)` → may now take a context.
- `DistributionKeeper.FundCommunityPool` — possible signature change.
- `sdk.AccountI` — may have added required methods on the v0.54 base.

The authoritative reference for each interface's new shape is the SDK source:
- `AccountKeeper`: https://github.com/cosmos/cosmos-sdk/blob/v0.54.2/x/auth/keeper/keeper.go
- `BankKeeper`: https://github.com/cosmos/cosmos-sdk/blob/v0.54.2/x/bank/keeper/keeper.go
- `StakingKeeper`: https://github.com/cosmos/cosmos-sdk/blob/v0.54.2/x/staking/keeper/keeper.go
- `DistributionKeeper`: https://github.com/cosmos/cosmos-sdk/blob/v0.54.2/x/distribution/keeper/keeper.go

To fetch SDK source (quote the URL — zsh treats `?` as a glob otherwise):

```bash
gh api 'repos/cosmos/cosmos-sdk/contents/x/auth/keeper/keeper.go?ref=v0.54.2' --jq '.content' | base64 -d
```

- [ ] **Step 4.1: For each method with a compile error in `interfaces.go`, update the signature**

Update only methods flagged in `/tmp/sdk54-build-errors.log`. Preserve method order. Do NOT add methods the module doesn't already call — we're narrowing the interface.

- [ ] **Step 4.2: Patch `clawback_vesting_account.go` only if forced**

If the error log shows `*ClawbackVestingAccount does not implement sdk.AccountI: missing method Foo`:

1. Look up the method signature in SDK 0.54.2's interface definition.
2. If `BaseVestingAccount` (which we embed) provides the method, we inherit — the error shouldn't appear.
3. If not, add a minimal stub on `ClawbackVestingAccount` that delegates where possible, or returns a zero value with a comment pointing at the upgrade.

Keep stubs short — single-line where possible.

- [ ] **Step 4.3: Patch `codec.go` only if forced**

If the error log mentions `codec.go`, the most likely fix is updating an interface registration target (e.g., type assertion against a renamed interface). Make only the change required by the compile error.

- [ ] **Step 4.4: Build the types package**

Run: `go build ./x/vesting/types/...`
Expected: package compiles cleanly. Errors in dependent packages (keeper, ante, module) are still fine — they're addressed in later tasks.

- [ ] **Step 5.2: Fix call sites**

Common patterns (from prior upgrades):
- A keeper method now returns `(T, error)` where it returned just `T`: capture the error.

- `module.AppModuleBasic`, `module.HasGenesisBasics`, `module.HasGenesis`, `module.HasServices`, `appmodule.AppModule`, etc. — if a satisfaction check fails, look at SDK 0.54.2 `types/module/module.go` and `cosmossdk.io/core/appmodule@v1.1.0` for the new interface shape.
- If an interface was renamed or removed, update the `var _ ... = ...` assertion. If an interface no longer exists, remove only that specific assertion. Do NOT add new interface satisfactions that aren't already asserted.
