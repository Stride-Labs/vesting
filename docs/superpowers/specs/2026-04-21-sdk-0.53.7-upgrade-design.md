# Cosmos SDK 0.53.7 Upgrade — Design

## Goal

Upgrade `github.com/evmos/vesting` from cosmos-sdk `v0.50.14` to `v0.53.7`. This module is consumed as a library by a downstream project that requires SDK 0.53; the upgrade exists purely to resolve that version incompatibility.

**Scope discipline:** absolute minimum changes required to compile and pass existing tests. No adoption of new 0.53 idioms, no "while we're here" cleanups, no refactors, no test additions.

## Motivation

A downstream Stride project pins SDK 0.53.x. Without this bump, MVS resolution fails. Nothing else about this module's behavior or API should change.

## `go.mod` Changes

Direct dep bumps:

- `github.com/cosmos/cosmos-sdk`: `v0.50.14` → `v0.53.7`
- `github.com/cometbft/cometbft`: `v0.38.17` → `v0.38.21` (matches SDK 0.53.7's own pin and the downstream pin)

Replace-directive changes:

- Drop `cosmossdk.io/core => cosmossdk.io/core v0.11.0`.
  - Original purpose was to work around a rosetta issue under SDK 0.50.
  - SDK 0.53.7 pins `cosmossdk.io/core v0.11.3` directly and does not import rosetta transitively, so the replace is stale and will fight MVS.
- Keep all other replace directives as-is: `99designs/keyring`, `btcsuite/btcd`, `gogo/protobuf`, `syndtr/goleveldb`.

Final step: `go mod tidy` to let the rest of the transitive deps resolve.

## Likely Compile-Fix Hot Spots

These are the files most likely to need changes based on known areas of drift between SDK 0.50 and 0.53. They are hypotheses, not a prescription — the compiler drives the actual change list.

- `x/vesting/types/interfaces.go` — expected keepers (`AccountKeeper`, `BankKeeper`, `StakingKeeper`, `DistributionKeeper`). Method signatures may have shifted.
- `x/vesting/types/codec.go` — interface registration for `sdk.AccountI`, `authtypes.GenesisAccount`, `govv1beta1.Content`. `AccountI` is the most likely drift point.
- `x/vesting/types/clawback_vesting_account.go` — implements `vestexported.VestingAccount` and `authtypes.GenesisAccount`. Updates required if the underlying sdk-vesting interface changed.
- `x/vesting/module.go` — `AppModule` / `AppModuleBasic`. May need to satisfy new interface methods only if 0.53 forces it.
- `x/vesting/keeper/*.go` (keeper, msg_server, grpc_query, gov, utils) — keeper call sites against updated keeper interfaces.
- `ante/vesting.go` — references `bank.AccountKeeper` and `stakingkeeper.Keeper` types; will re-point if signatures changed.
- `.pb.go` files — leave alone unless they reference removed SDK types. If forced, regenerate via `make proto-gen`.

## Explicitly Out of Scope

The following are deliberately not part of this upgrade, even if 0.53 nudges toward them:

- Migration to `cosmossdk.io/collections` storage.
- Moving `ClawbackProposal` from `govv1beta1.Content` to `govv1.Msg`.
- Adoption of `appmodule.Environment`, `HasPreBlocker`, `HasABCIEndBlocker`, or other new module interfaces — unless the compiler requires implementing them.
- Adoption of `x/accounts`.
- Test additions, refactors, renames, doc updates.
- Consensus-version bump.
- Changes to AnteHandler logic. Only its referenced types may change.

## Verification

Done means all of the following pass on branch `v1.0.0-check-base-account-sdk-53`:

- `go build ./...` clean.
- `go vet ./...` clean.
- `go test ./...` passes. Existing tests: `x/vesting/types/proposal_test.go`, `x/vesting/types/schedule_test.go`.

## Risks and Open Questions

- **`sdk.AccountI` shape change.** If 0.53 added required methods, `ClawbackVestingAccount` needs small stubs. Forced, minimal.
- **`.pb.go` forced regeneration.** If generated code references removed SDK types (e.g., an old cosmos-proto annotation), we must regenerate via the proto-builder Docker image. Flag this to the user if encountered.
- **Msg proto annotations.** If the registered `Msg` service uses an annotation 0.53 rejects at interface-registration time, same regen story.
- **Transitive replace clashes.** `gogo/protobuf => regen-network/protobuf` may conflict with SDK 0.53's proto toolchain. If `go mod tidy` fails, address surgically rather than broadly.

## Deliverable

A single commit on branch `v1.0.0-check-base-account-sdk-53` bumping the module to SDK 0.53.7 with the branch building green and existing tests passing.
