# Cosmos SDK 0.54.2 Upgrade — Design

## Goal

Upgrade `github.com/evmos/vesting` from cosmos-sdk `v0.53.7` to `v0.54.2`. As with the previous bump, this exists purely to keep this library consumable by a downstream Stride project that wants to track SDK 0.54.

**Scope discipline:** absolute minimum changes required to compile and pass existing tests. No adoption of new 0.54 idioms (`appmodule.Environment`, OpenTelemetry, BlockSTM, AuthorityParams, store/v2 features), no "while we're here" cleanups, no refactors, no test additions. Final state is **left unstaged** — no commit at the end of this upgrade.

## Motivation

A downstream Stride project pins SDK 0.54.x. Without this bump, MVS resolution fails. Nothing else about this module's behavior or API should change.

## What Actually Changes for Us

The SDK 0.54.x upgrade guide ([UPGRADING.md](https://github.com/cosmos/cosmos-sdk/blob/v0.54.2/UPGRADING.md)) lists many changes — most are app-level concerns (gov keeper wiring, EndBlocker order, NodeService, IBC v11, etc.) that don't apply to a standalone vesting library. The two that do apply are:

1. **`cosmossdk.io/log` → `cosmossdk.io/log/v2`.** The log module bumped to v2. Direct importers must update the path.
2. **`cosmossdk.io/store` is gone — store moved into the SDK as a sub-module.** `cosmossdk.io/store/types` becomes `github.com/cosmos/cosmos-sdk/store/v2/types`.

Plus the indirect / transitive bumps in `go.mod`.

The other guide-level items (gov keeper wiring, EndBlock ordering, NodeService registration, removed `cosmossdk.io/x/{evidence,feegrant,upgrade,tx}` modules, deprecated `x/{circuit,nft,crisis}`, `x/group` going Enterprise, BlockSTM, AuthorityParams, IBC v11, telemetry/OpenTelemetry) are out of scope: this module doesn't wire keepers or import the affected packages.

## `go.mod` Changes

Direct dep bumps:

- `github.com/cosmos/cosmos-sdk`: `v0.53.7` → `v0.54.2`
- `github.com/cometbft/cometbft`: `v0.38.21` → `v0.39.1` (matches SDK 0.54.2's pin; was previously indirect — may stay indirect after tidy)
- `cosmossdk.io/core`: `v0.11.3` → `v1.1.0`
- `cosmossdk.io/errors`: `v1.0.2` → `v1.1.0`
- `cosmossdk.io/store v1.1.2`: **remove** (no longer a separate module)
- `cosmossdk.io/log v1.6.1`: **remove**, replace with `cosmossdk.io/log/v2 v2.1.0`
- `cosmossdk.io/math`: `v1.5.3` (unchanged)

Replace-directive review:

- Keep `99designs/keyring` (SDK still uses it).
- Keep `syndtr/goleveldb` (SDK still uses it).
- `gogo/protobuf => regen-network/protobuf`: drop only if `go mod tidy` resolves cleanly without it. SDK 0.54.2's own go.mod no longer has this replace, so it's likely stale, but it doesn't conflict the way the old `cosmossdk.io/core => v0.11.0` replace did. Try without; restore if tidy or build fails.
- `btcsuite/btcd v0.22.2`: drop unless something needs it. Same logic — SDK 0.54.2 doesn't pin this.

Go directive: SDK 0.54.2 declares `go 1.25.9`, our `go.mod` declares `go 1.23.2` / `toolchain go1.23.6`. We may need to bump our `go` line to satisfy the SDK's minimum. Address only if `go mod tidy` complains.

Final step: `go mod tidy` to resolve the rest of the transitive deps.

## Likely Compile-Fix Hot Spots

Hypotheses, not a prescription — the compiler drives the actual change list.

- `x/vesting/keeper/keeper.go` — the only file with a direct `cosmossdk.io/log` and `cosmossdk.io/store/types` import. Both must update. Forced.
- `x/vesting/types/interfaces.go` — expected keeper interfaces (`AccountKeeper`, `BankKeeper`, `StakingKeeper`, `DistributionKeeper`). v0.53 already moved these to `context.Context`, so additional drift in 0.54 is likely small. Possible: `BankKeeper.BlockedAddr` may have gained a context parameter. Possible: `DistributionKeeper.FundCommunityPool` may have changed signature.
- `x/vesting/types/clawback_vesting_account.go` — implements `vestexported.VestingAccount` and `authtypes.GenesisAccount`. If 0.54's `sdk.AccountI` added required methods that `BaseVestingAccount` doesn't satisfy, we'd need stubs.
- `x/vesting/types/codec.go` — interface registration. Stable in 0.53, likely stable in 0.54.
- `x/vesting/module.go` — `AppModule` / `AppModuleBasic`. May need to satisfy new core/appmodule interface methods only if 0.54 forces it.
- `x/vesting/keeper/{msg_server,grpc_query,gov,utils}.go` — call sites against updated keeper interfaces.
- `ante/vesting.go` — references `bankkeeper.Keeper` and `stakingkeeper.Keeper` types; may need to re-point if signatures changed.
- `.pb.go` files — leave alone unless they reference removed SDK types. If forced, regenerate via `make proto-gen`.

## Explicitly Out of Scope

The following are deliberately not part of this upgrade, even if 0.54 nudges toward them:

- Migration to `cosmossdk.io/collections` storage.
- Migration to store v2 (we keep the legacy `store/v2/types` types — the v2 sub-module exposes both legacy types and the new store v2 API; we use only `StoreKey`, which is unchanged).
- Adoption of `appmodule.Environment`, `HasPreBlocker`, `HasABCIEndBlocker`, or other new module interfaces — unless the compiler requires them.
- Adoption of `x/accounts`.
- OpenTelemetry, AuthorityParams, BlockSTM, IBC v11, x/group → Enterprise.
- Test additions, refactors, renames, doc updates.
- Consensus-version bump.
- Changes to AnteHandler logic. Only its referenced types may change.
- Moving `ClawbackProposal` from `govv1beta1.Content` to `govv1.Msg`.

## Verification

Done means all of the following pass on branch `v1.0.0-check-base-account-sdk-54`:

- `go build ./...` clean.
- `go vet ./...` clean.
- `go test ./...` passes. Existing tests: `x/vesting/types/proposal_test.go`, `x/vesting/types/schedule_test.go`.

## Risks and Open Questions

- **`sdk.AccountI` shape change.** If 0.54 added required methods, `ClawbackVestingAccount` needs small stubs. Forced, minimal.
- **Keeper interface signature drift.** Less likely than the 0.50→0.53 jump (which added `context.Context`), but possible. Driven by compiler.
- **Go directive bump.** If `go mod tidy` insists on Go 1.24+ to satisfy SDK 0.54.2's `go 1.25.9` minimum, bump our `go` directive accordingly. Don't bump pre-emptively.
- **`gogo/protobuf` replace.** Removing it might cause `.pb.go` regen drift; if so, restore. Don't fight it.
- **`.pb.go` forced regeneration.** If generated code references removed SDK types, regenerate via the proto-builder Docker image. Flag to user if encountered.

## Deliverable

A green `v1.0.0-check-base-account-sdk-54` branch with the SDK 0.54.2 bump applied. Changes are **left unstaged** (per user request) — no commit, no `git add`. The user can review and commit themselves.
